# PortaGraph

Веб-система, которая анализирует несколько репозиториев как одну систему: сама определяет роль каждого репозитория, строит карту архитектуры со связями между сервисами, отвечает на вопросы по коду со ссылками на файлы и строки, оценивает последствия изменений и формирует документацию.

Учебный проект по дисциплине «Программная инженерия», группа ПИ24, КубГАУ.
Команда: **Казанкова Анастасия** (тимлид, backend и архитектура), **Чиженко Максим** (анализ кода, AI, frontend).

## Быстрый старт

Нужны **Python 3.10+** и **PostgreSQL 14+** (для подключения Git-репозиториев ещё **git**).

```bash
# Windows: двойной щелчок по start.bat
# macOS / Linux:
./start.sh
```

Скрипт создаёт виртуальное окружение, ставит зависимости и запускает сервер. Откройте http://localhost:8000.

По умолчанию приложение подключается к `postgresql://postgres:postgres@127.0.0.1:5432/portagraph` и **само создаёт базу и таблицы**. Другой адрес — в файле `.env` (образец — `.env.example`).

При первом запуске создаётся демо-проект **ShopFlow** (9 репозиториев на Java, Kotlin, Python и TypeScript), уже проанализированный, и три пользователя. Пароль у всех — `portagraph`:

| Пользователь | Почта | Роль в ShopFlow |
|---|---|---|
| Анастасия Казанкова | anastasia@portagraph.local | Владелец |
| Максим Чиженко | maxim@portagraph.local | Разработчик |
| Гость | guest@portagraph.local | Наблюдатель |

На странице входа их можно выбрать одним щелчком.

**Через Docker:** `docker compose up --build`. Поднимутся PostgreSQL и приложение на http://localhost:8000.

**Вручную:**

```bash
python -m venv .venv && . .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt
python run.py
```

**Тесты** (нужен запущенный PostgreSQL, тестовая база `portagraph_test` создаётся и удаляется сама):

```bash
python -m unittest discover -v tests
```

## Как это работает

### Определение роли репозитория

Эвристики по структуре и коду (`portagraph/core/roles.py`): точка входа (`main`, `@SpringBootApplication`, FastAPI, Express), Dockerfile, веб-фреймворки — сервис; Next.js/React — фронтенд; только сборка артефакта без точки входа — библиотека; compose, Terraform, Helm, Kubernetes — инфраструктура. Каждая роль сопровождается уверенностью и списком причин, которые видны в панели узла.

### Связи и уверенность

| Признак в коде | Связь | Уверенность |
|---|---|---|
| URL сервиса в коде (`http://auth-service:8080`) | CALLS_HTTP | 0,90 |
| URL сервиса в конфигурации | CALLS_HTTP | 0,85 |
| Feign-клиент | CALLS_HTTP | 0,90 |
| `kafkaTemplate.send("topic")`, `@KafkaListener`, `consumer.subscribe([...])` | PUBLISHES / CONSUMES | 0,85–0,90 |
| Строка подключения к БД | READS_WRITES | 0,85 |
| Зависимость на артефакт другого репозитория (Maven, Gradle, npm) | DEPENDS_ON | 0,95 |
| Внешний API (`https://api.mailgun.net`) | CALLS_HTTP | 0,75 |
| `depends_on` в docker-compose | DEPENDS_ON | 0,60 |
| Имя сервиса только в переменной окружения | CALLS_HTTP | 0,50 |

Если одну связь подтверждают несколько признаков, уверенности объединяются: `1 − Π(1 − cᵢ)`, но не выше 0,98. Связи ниже **0,35** отбрасываются, ниже **0,7** показываются пунктиром и попадают в «Требуют проверки». Подтверждённая архитектором связь получает уверенность 1,0.

### Impact analysis

Обход графа в ширину от изменяемых компонентов к их потребителям (ребро «A → B» значит «A зависит от B»; для публикации в топик направление обратное — изменение издателя затрагивает топик и его подписчиков). Изменение сервиса включает изменение всех его классов.

Вес потребителя: `вес(узла) × 0,6 × max(0,1; уверенность связи)`, у изменяемого узла вес 1.

| Риск | Условие |
|---|---|
| Критический | ≥ 4 прямо затронутых сервисов или суммарный вес ≥ 4 |
| Высокий | ≥ 2 прямо затронутых сервисов или суммарный вес ≥ 2 |
| Средний | затронут хотя бы один компонент |
| Низкий | зависимых компонентов нет |

### Ассистент (демо-режим без языковой модели)

Ключа к LLM в проекте нет, поэтому ассистент работает без неё:

1. Находит в вопросе компоненты графа (сервисы, топики, базы, классы), в том числе по русским синонимам («заказ» → order, «оплата» → payment).
2. Определяет намерение: «кто использует», «от чего зависит», «за что отвечает», «где хранится». Ответ строится по рёбрам графа с доказательствами.
3. Добавляет 12 лучших фрагментов полнотекстового поиска PostgreSQL (`tsvector`, GIN) только по коду этого проекта.

Ответ с уверенностью ниже **0,4** помечается предупреждением о неполных данных. Подключить LLM можно в одном месте — `portagraph/services/assistant.py`: найденные фрагменты уже собраны как контекст.

### Безопасность

* Секреты (ключи AWS, токены GitHub/Slack/Bitbucket, JWT, приватные ключи, пароли в строках подключения и конфигурации) маскируются до индексации; файлы `.env`, `*.pem`, `*.key` не индексируются.
* Токены доступа к репозиториям шифруются (Fernet), в URL клона подставляются только на время команды.
* ZIP: защита от выхода за пределы каталога и от «zip-бомб».
* Права проверяются на сервере для каждого действия, данные изолированы по проектам.

## Структура

```
portagraph/
  core/        алгоритмы без зависимостей от веба: граф, impact, роли, связи, разбор кода, секреты
  db/          собственный драйвер PostgreSQL (wire protocol v3, SCRAM-SHA-256), пул, миграции
  services/    бизнес-логика: проекты, репозитории, конвейер анализа, граф, ассистент, impact, документы, веб-хуки
  web/         Flask: страницы, JSON API, приём веб-хуков
  templates/   Jinja-шаблоны экранов Э-01…Э-13
  static/      оформление в стиле Omega, рендерер графа на SVG
  demo/        исходники демо-системы ShopFlow
tests/         модульные и интеграционные тесты (unittest)
prototype/     первый прототип на Java/Spring Boot и Next.js (спринты 1–2)
docs/          артефакты 1–12, глоссарий, диаграммы, макеты
```
